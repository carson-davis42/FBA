# FBAJC 6c (history) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. The user wants a one-sentence status line as each task finishes.

**Goal:** Bring FBAJC S1–S78 into the History tabs: per-season summaries from the user's history sheets, March Madness and NIT brackets from the bracket PDF, school history pages, and an FBAJC option in `HistoryLeagueSwitch`.

**Architecture:** Importers (`web/importers/`) build and validate docs and write only to a `--data <dir>`; the pages read them through `useDoc`; pure derivations live in `web/engine/history/jc.ts`. Copy the shape of the D2 history (`importers/d2History.ts`, `importers/sheets/d2History.ts`, `engine/history/d2.ts`, `app/history/d2/*`) and of the past brackets (`importers/history/convertBrackets.ts`, `mergeBrackets.ts`).

**Tech Stack:** TypeScript 5, zod 3 (strict), React 18, React Router 6, Vitest 2 (globals off).

Spec: `docs/superpowers/specs/2026-10-01-fbajc-history-6c-design.md` (read it first, then `2026-10-01-fbajc-design.md` §1 "History (6c)" and `2026-10-01-fbajc-6b-design.md`).

## Global Constraints

- Run from `web/`: `npx vitest run <paths>`; `npx tsc --noEmit` must print nothing. `web/data.test.ts` must keep passing.
- Never modify `web/data/**`, `FBA/`, `FBAD2/`, `FBAJC/`, `FBAWC/`, `FBA Logos/`. Importer tests use in-memory fixtures or a temp copy under the OS temp dir, never `web/data`. Do not start or stop the dev servers. Leave no stray files; scratch goes in `.superpowers/sdd/` (git-ignored; absent in the cloud checkout, so use the session scratchpad there). Stage files by explicit path.
- The user runs the importers on the real data. Every import mode requires `--data <dir>` (`requireDataDir`), validates every built doc through `schemaForPath` first, and writes nothing on failure. S79 and later are never written.
- Commit trailer: the one in the repo `CLAUDE.md`.
- Schemas are `.strict()`; each saved doc has a schema in `engine/shared/types.ts` and a path rule in `engine/shared/schemaRegistry.ts`. All additions to `SummaryFile`/`JcSummary` are optional so the committed S78 summary and every 6b app-written summary stay valid.
- Every jsdom test file calls `cleanup()` in `afterEach`. Tests sit next to the source. RED first.
- Pages: tables inside `.table-wrap`, theme tokens, no horizontal page scroll at 375px; a page for a season with no data must not title itself with the current season.
- Browser checks cannot run in the cloud checkout (no `.superpowers/` scratch tooling): say so in the final report; do not claim them.
