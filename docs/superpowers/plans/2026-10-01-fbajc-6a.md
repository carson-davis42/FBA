# FBAJC 6a (regular season) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Play the FBAJC regular season in the web app: start the season, 29 days of games (preseason tournaments, conference challenge, conference play) with in-season rating progression, rankings, conference standings with clinch bars, and the pages and calendar wiring for it.

**Architecture:** Pure TypeScript under `web/engine/jc/`; every random choice takes an injected `Rng`. Games reuse `simGame` (`engine/season/sim.ts`) and `toGameResult` (`engine/season/moves.ts`). Two new saved docs per season (`schedule.json`, `rankings.json`, shapes in Task 1); results go in the existing `results.json` (`ResultsFile`), ratings and points in the existing `rosters.json`. Pages under `web/app/jc/`, mirroring `app/wc/` (`useWcDocs`, `useWcRun`) and `app/season/`.

**Tech Stack:** TypeScript 5, zod 3 (strict), React 18, React Router 6, Vitest 2 (globals off).

Spec: `docs/superpowers/specs/2026-10-01-fbajc-design.md` (read it first). Java reference (read-only): `FBAJC/src/fbajc/` (`Main.java`, `FootballRanker.java`, `PreSeasonTourny.java`, `Team.java`).

- Every random choice takes an injected `Rng` (`engine/d2/random.ts`: `mulberry32`, `randInt`, `shuffle`); no `Math.random` in the engine. Pages pass `Math.random`.
- Moves return `{ ok: true, state, changed, label }` or `{ ok: false, problems }` (mirror `WcResult`/`wcFail` in `engine/wc/state.ts`).
- Zod schemas are `.strict()`. Each saved doc has a schema in `engine/shared/types.ts` and a path rule in `engine/shared/schemaRegistry.ts`. `web/data.test.ts` must keep passing.
- Saves use optimistic concurrency: go through `commitDocs` (`app/roster/commit.ts`) with the loaded versions (missing doc = version null); chained saves use the versions returned by the previous save. Guard saving handlers with a `useRef` (`useSaving()` forces an extra render). "Play day" and "Play to end" simulate in memory and save once.
- Every jsdom test file calls `cleanup()` in `afterEach`. Tests sit next to the source (`x.ts` / `x.test.ts`). Run RED first.
- A page for a season whose stage doesn't exist must not title itself with the current season.
- Calendar-driven pages need the `leagueSections` entry in `app/shell/SectionNav.tsx` as well as routes.
- Rules (spec §1): 216 teams, 18 conferences of 12 (`teams.json` `group`); 29 days, one game per team per day, 108 games a day, 3132 games. Days 1–3 preseason tournaments (27 tournaments of 8, 12 games each, 4 games per tournament per day); days 4–7 conference challenge (4 sets, each pairs the 18 conferences into 9 pairs); days 8–29 conference play (22 rounds, double round-robin per conference). Home has no advantage.
- Standings tiebreaks: conference games back, fewer conference games played, overall win%, ranking position (ranked beats unranked), then head-to-head, point differential, stored random draw.
- Ratings progress after every regular-season and preseason-tournament game (`updatePlayerRatings`, `Main.java:1639`); points are recorded in every game.
- Walk-ons already exist (part 7c: `engine/college/walkOns.ts`, unnamed players with `name: null`). Season start requires no open roster spots; "Names needed" = unnamed players past the Java thresholds (Jr ≥ 80, So ≥ 78, Fr ≥ 76).

### Task 2: Challenge sets and conference rounds

- `challengeSets(confs: Record<string, string[]>, rng: Rng): Pair[][]`: 4 sets (one per day 4–7). Each set pairs the 18 conferences into 9 pairs by shuffled order, with no conference pair repeated across the 4 sets (an 18-team round-robin 1-factorization: use the circle method on a shuffled conference order and take the first 4 rounds), shuffles both teams lists and matches them in order, random home/away. ### Task 5: Day play and rating progression

**Files:** Create `web/engine/jc/play.ts`, `web/engine/jc/play.test.ts`.

**Consumes:** `JcState`, `JcResult`, `dayGames` (Task 3), `blendRankings`, `teamRating` (Task 4), `simGame` and `SimTeam` (`engine/season/sim.ts`), `toGameResult` (`engine/season/moves.ts`), `lineup`-style building from a roster (see `lineup` in `engine/season/moves.ts`).

**Produces:**
- `playerLine(...)`: no new export; internal.
- `progressRatings(roster: RosterEntry[], lastPoints: Record<string, number>, won: boolean, oppRating: number, avgRating: number, rng: Rng): RosterEntry[]`: port `updatePlayerRatings` (`Main.java:1639`) exactly: `chance = (99 − rating + lastPoints/2) × 2/3` (integer), then ×5/9 (≥90), ×5/8 (≥82), ×5/7 (≥72), ×5/6 (≥65) with integer division, then `mult = clamp(0.8, 1.2, 1 + 0.02 × (oppRating − avgRating))`, `chance = round(chance × mult)`, halved (integer) after a loss, then the repeated-halving loop against `randInt(rng, 0, 99)`; cap 99. `lastPoints` is points in the game just played.
- `playDay(state: JcState, rng: Rng): JcResult`: plays the next unplayed day (all 108 games, simulated in memory) and returns the updated state: tournament days 2–3 build their games from `dayGames` first (append to `schedule.days[].games`, with the fixed numbering `(day−1)×108+index+1`); each game uses `simGame(gameNo, home, away, rng)` with lineups from `rosters` at that moment; `toGameResult` appended to `results` (create the doc when missing: `{league:'fbajc', season, locked:false, games:[]}`); every player's `points` increases by the box points; after each game both teams' starters progress via `progressRatings` (team ratings and the league average are recomputed after each game, as the Java does); after the day, a `rankings` snapshot `{afterDay, order}` is appended from `blendRankings`. `changed: ['schedule' (only if days 2–3 were filled), 'results', 'rosters', 'rankings']`. Refuses when: the calendar's `fbajc` step isn't current (use `calendarProblem` from `engine/season/moves.ts`), no schedule, or the regular season is over.
- `playToEnd(state: JcState, rng: Rng): JcResult`: repeats `playDay` in memory until day 29 is played; one result, label `Play to end of regular season`. Refuses if already over.
- `regularSeasonOver(state: JcState): boolean`.
